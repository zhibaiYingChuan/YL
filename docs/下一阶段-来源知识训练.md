# 下一阶段：来源知识训练

## 1. 目标

让道体学习动态 ELF 初始化过程中 `dl_main` 局部变量 `main_map` 的真实来源模式，而不是在断言前重复修复 `_ns_loaded` 或 `_dl_rtld_map.l_next`。

本阶段的验收目标是：

1. 断言前现场能够持久化为非测试 JSONL；
2. 每条现场样本同时保存输入证据、监督来源标签、证据来源和置信度；
3. 双梯形网络能够对来源标签输出可审计置信度；
4. 阶段 4 只根据来源推理结果确认或拒绝，不直接写入状态；
5. 在真实 `hello_dynamic` 现场中，正确来源标签的置信度达到 `> 0.8`，否则阶段 4 必须拒绝来源确认。

本阶段不以暂时通过 glibc 断言作为训练成功标准。训练成功必须同时满足数据可追溯、标签有证据、推理结果可复现。

## 2. 训练数据来源

### 2.1 当前现场证据

来源于解释器断言前的 `MainMapSourceEvidence`，包括：

- `rip`：断言前指令地址；
- `rbp`：当前帧指针；
- `rsp`：当前栈指针；
- `rax`、`rdi`：断言循环中的关键寄存器；
- `[rbp]`：帧指针直接槽位；
- `[rsp]`：当前栈顶槽位；
- `[rax + 0x18]`：当前 link_map 链接值；
- `[rdi]`：namespace loaded 值；
- `_ns_loaded`：动态 `_rtld_global` 中的 namespace loaded 值。

当前已观察到两条现场：

```text
现场 A：
rbp = 0x2f3a000
rax = 0x2700000
[rax + 0x18] = 0x2f3a000
[rdi] = 0x2f3a000
_ns_loaded = 0x2f3a000

现场 B：
rbp = 0x2f3a000
rax = 0x2f3a000
[rax + 0x18] = 0
[rdi] = 0x2f3a000
_ns_loaded = 0x2f3a000
```

这两条证据支持以下可审计事实：

```text
rbp 始终等于 main_map 候选地址；
rax 在断言循环中从 _dl_rtld_map 链接到 main_map；
main_map.l_next 在第二次检查时为 0；
_ns_loaded 仍然指向 0x2f3a000。
```

“`main_map` 来源是 `rbp`”是当前的高可信候选结论，但在更多现场和前序写入证据完成前，不得把它写成无条件事实。

### 2.2 后续现场

每次真实运行都应继续收集：

- 断言前至少两个连续命中点；
- 进入 `dl_main` 后的寄存器变化；
- `[rbp + offset]` 和 `[rsp + offset]` 的候选槽位；
- 写入候选槽位的前序 `rip`、opcode、值和宽度；
- 候选值与 `_ns_loaded`、`main_map` 的相等关系。

禁止使用人工指定的绝对地址作为来源证据。

## 3. 标签定义

来源标签属于知识字段，不属于可直接写入解释器内存的状态字段。

### 3.1 主标签

```text
source.main_map.rbp
source.main_map.rsp_slot
source.main_map.register
source.main_map.link_map_l_next
```

含义：

| 标签 | 含义 |
|---|---|
| `source.main_map.rbp` | `main_map` 候选值来自当前帧指针或其帧槽位 |
| `source.main_map.rsp_slot` | `main_map` 候选值来自当前栈帧槽位 |
| `source.main_map.register` | `main_map` 候选值来自通用寄存器 |
| `source.main_map.link_map_l_next` | `main_map` 候选值来自 `_dl_rtld_map.l_next` 链接遍历 |

### 3.2 监督规则

第一版监督规则采用证据约束，而不是只按日志文本标注：

```text
rbp == ns_loaded
且 rbp == main_map 候选值
且连续现场中 rbp 保持稳定
→ source.main_map.rbp = 1.0
```

```text
rax_l_next == main_map 候选值
且 rax 从 _rtld_map 过渡到 main_map
→ source.main_map.link_map_l_next = 1.0
```

```text
rsp 槽位值与 main_map 候选值相等
且存在前序写入证据
→ source.main_map.rsp_slot = 1.0
```

```text
只有寄存器值相等但没有来源指令或连续现场支持
→ source.main_map.register 作为候选，不直接标记为确定事实
```

### 3.3 标签安全边界

来源标签不能进入 `StateApplier` 的可写字段白名单。阶段 4 的输出只用于：

- 来源确认；
- 继续采集；
- 拒绝不充分证据；
- 生成下一轮训练样本。

不得因为来源置信度高就自动修改 `_ns_loaded`。

## 4. 训练数据格式

建议在 `knowledge/glibc_main_map_sources.jsonl` 中每行保存一条完整样本：

```json
{
  "context": "main_map_source_observation",
  "input_vector": [0.0],
  "output_vector": [0.0],
  "source": "DebugLog",
  "target_fields": [
    "source.main_map.rbp",
    "source.main_map.rsp_slot",
    "source.main_map.register",
    "source.main_map.link_map_l_next"
  ],
  "evidence_url": "runtime://hello_dynamic/assertion/0x270abf3",
  "evidence_confidence": 0.8,
  "evidence": {
    "rip": "0x270abf3",
    "rbp": "0x2f3a000",
    "rsp": "0x2f32c00",
    "rax": "0x2700000",
    "rdi": "0x2733a50",
    "rbp_slot": "0x2f3a000",
    "rsp_slot": null,
    "rax_l_next": "0x2f3a000",
    "rdi_value": "0x2f3a000",
    "ns_loaded": "0x2f3a000"
  },
  "supervision": {
    "source.main_map.rbp": 1.0,
    "source.main_map.rsp_slot": 0.0,
    "source.main_map.register": 0.5,
    "source.main_map.link_map_l_next": 1.0
  }
}
```

实际实现时必须保持 `input_vector` 和 `output_vector` 为 `KNOWLEDGE_VECTOR_DIM` 维，不能使用示例中的单元素数组。

## 6. 训练方式

### 6.1 第一阶段：确定性监督初始化

利用真实证据构造来源标签监督向量：

```text
现场证据
→ 规则标注来源标签
→ 输入向量：寄存器/栈/链表关系编码
→ 输出向量：来源标签监督值
→ 生成初始来源权重
```

这一步只能称为“监督初始化”，不能称为完整梯度训练。

### 6.2 第二阶段：误差反馈微调

当来源样本数量达到可用规模后，增加：

- 正确来源样本；
- 相似但错误来源样本；
- `rbp` 与 `ns_loaded` 不相等样本；
- `rsp` 槽位命中但 `rbp` 未命中样本；
- `rax.l_next` 为 0 的链尾样本；
- 多对象链中的非 main_map 样本。

使用来源标签损失进行微调，避免模型只记住“所有现场都选 rbp”。

## 7. 验证方式

### 7.1 离线验证

对保留的来源样本执行：

```text
输入现场 → 网络推理 → 来源标签置信度
```

验收要求：

- 正确来源标签置信度 `> 0.8`；
- 错误来源标签置信度 `< 0.2`；
- 输入向量、输出向量无 NaN/Inf；
- 训练样本来源和监督标签可追溯。

### 7.2 在线验证

运行：

```powershell
$env:DAOTI_TRACE_MAIN_MAP_SOURCE="1"
$env:DAOTI_TRACE_RUNTIME="1"
cargo run --bin daoti -- run ./fixtures/runtime/hello_dynamic
```

阶段 4 必须输出：

```text
TRACE daoti-main-map-source
source.main_map.rbp > 0.8
```

同时必须满足：

- 阶段 4 不调用 `StateApplier`；
- 不修改 `_ns_loaded`；
- 不修改 `_dl_rtld_map.l_next`；
- 输出完整的 `MainMapSourceEvidence`；
- 若置信度不足，明确拒绝来源确认。

### 7.3 当前预期结果

在来源权重尚未重新训练前，当前输出为 `0.0` 是预期的，不能视为训练通过。只有完成来源监督数据生成并重新加载权重后，才进行 `> 0.8` 验收。

## 8. 交付顺序

1. 持久化 `MainMapSourceEvidence`；
2. 生成来源监督 JSONL；
3. 生成来源专用或来源增强权重；
4. 加载新权重运行阶段 4；
5. 验证来源置信度；
6. 在来源证据不足时验证拒绝路径；
7. 最后再判断是否需要任何状态应用变化。

在第 5 步通过前，不得宣称道体已经学会 `main_map` 来源，也不得宣称 `hello_dynamic` 已完成端到端闭环。

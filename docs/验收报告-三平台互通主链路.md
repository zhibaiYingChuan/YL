## 三、可交付成果

### 3.1 静态 ELF 解释器

**入口：** `daoti_core::elf::execute_elf_file()`
**CLI：** `daoti run <静态ELF文件>`
**验证：** `hello_static.elf` 输出 `Hello World`，退出码 0
**解释器：** `X86_64Interpreter` + `NativeSyscallBridge`
**支持：** 静态链接 x86_64 ELF 二进制，含 libc 独立 syscall 直通

### 3.2 Mach-O 解释器

**入口：** `daoti_core::macho_runtime::execute_macho_file()`
**CLI：** `daoti run <Mach-O文件>`
**验证：** `macho_console_fixture` 输出 `macho-runtime-ok`，退出码 7
**解释器：** `X86_64Interpreter` + `DarwinBridge`
**支持：** Mach-O 64-bit 及 Fat/Universal Mach-O，控制台 write syscall 映射

**退出码说明：** Mach-O 程序预期退出码为 7（由 fixture 定义）。非零退出码是预期行为，不代表执行失败。

### 3.4 PE 解释器（已修复）

**入口：** `daoti_core::parser::pe::execute_pe32_plus_console()`
**CLI：** `daoti run <PE.exe文件>`
**验证：** `test_execute_self_contained_pe_fixture` 输出 `Hello, PE!`，退出码 0
**解释器：** `X86_64Interpreter` + `PeConsoleShim`
**支持：** PE32+ (x64) 控制台程序，WriteFile/WriteConsoleA/GetStdHandle/ExitProcess 等 API shim

**退出码说明：** PE 第一阶段 fixture 通过 `ExitProcess(0)` 正常退出；输出与退出码共同作为解释器验收条件。

**本次修复的三处 bug**（小节 4.2 已从"已知限制"移除）：
1. **API shim 地址重叠**：`PeApiAddressMap` 中 6 个 stub 原先全部指向同一个 `shim_base`，导致 `MemoryModel::add_region` 段重叠拒绝映射。已改为每个 stub 间隔一页。
2. **初始 RSP 无 headroom**：初始 RSP 被顶到栈区上界，Windows x64 入口代码按正偏移访问 `[rsp+0x40]`（shadow space/参数区）时越界。已按 ELF 路径一致，RSP 上方保留一页 headroom。
3. **WriteFile 未写回字节数**：`write` syscall 只把字节数返回 rax，未写回 `lpNumberOfBytesWritten`（`[r9]`），导致 `written==14` 判断失败，退出码误判为 1。已在 shim 中把计数写回 `args[5]`（r9）。

**PE 自包含验收命令：**
```powershell
cargo test -p daoti-core parser::pe::tests::test_execute_self_contained_pe_fixture --lib
```

**CLI 路由：** ✅ 已接入

**诊断：** `load_combined_dynamic()` 已完成 ELF 装载、依赖解析、重定位、AUXV 构造；ld-linux 可执行到 `0x270abf3`，但 glibc 的 `_rtld_global`、`link_map`、TLS、`_r_debug` 等运行时数据结构未初始化，访问 `addr=0x1ab88` 时触发段错误。

**建议：** 作为独立工作线推进，补齐 glibc 运行时模拟。当前不阻塞主链路交付。

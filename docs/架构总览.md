# 驭灵（道体）架构总览

> ## 最终目标（北极星 · 不可变）
>
> **驭灵最终必须实现 Windows / Linux / macOS 三平台任意软件互调：任意平台的二进制文件，在任意其他平台上无差别执行。**
>
> 当前所有阶段性方案（B0 / B1 / B2）均是通往此目标的**路径**，不是对目标的替代或缩窄。任何「当前仅支持 X→Y」的表述均为**阶段性聚焦**，macOS 等其余方向已在路线图中。

> 文档版本：v1.3 · 编制日期：2026-08-23 · 工程状态：模式A 已交付；模式B 仅有受控 fixture/解析基础能力，真实 libc stdout 回归未验收

本文档描述驭灵项目当前的完整架构、模块职责、数据流与功能实现方式。

***

## 0. 当前完成度 vs 远期目标（诚实定位）

> 本节用于校准「当前阶段已完成」与「最终目标」的边界。**最终目标见顶部「北极星」锚点，本节所述均为阶段性状态，不改变最终目标。**
> 原则：**能用的如实说，骨架的明确标注为骨架。**

| 维度 | 当前真实状态 | 远期目标 | 对外可宣称 |
|------|------------|---------|-----------|
| 平台覆盖 | 仅有受控 x86_64 ELF/ET_DYN 入口及 Mach-O/PE fixture 的解析或契约证据；真实 libc、通用 PE→Linux、Mach-O 执行均未验收 | Windows/Linux/macOS 三平台任意互调（最终目标） | 不得宣称通用跨平台执行；三平台互调为路线图 |
| 智能程度 | 确定性规则引擎（RuleEngine 五行表 + 20 条 syscall 映射）；B2 双梯形网络为**代码骨架** | 符号推演 + 双梯形网络真实参与在线决策 | 规则引擎 + 符号推演；非「完全 AI 驱动」 |
| B2 双梯形网络 | 骨架完成（网络数学/codec/gate/权重加载/降级）；三触发条件（覆盖率>80%、10 万配对日志、训练成功率>90%）**尚未满足**，gate 默认旁路 | 离线训练 + 数据积累后 gate 放行 | 架构已预留，**训练数据积累中** |
| 道体角色 | 编排器（确定性 if-else 编排 感知→推演→执行→降级） | 自主决策（上下文策略选择、自适应降级） | **编排器**，非推理引擎 |
| 产品阶段 | 模式A 生产可用；模式B B0/B1 可用；B2 骨架；学习闭环 feature 门控 | 完整三平台互调 + 学习闭环常开 | MVP+ 版本（通往最终目标的当前阶段） |

### 0.1 当前路线裁决（执行宪法 · 2026-08-17 长期方向对齐）

> **当前主路线：本地二进制信号重映射（B1/B2 终极形态）为唯一主干，不搞双轨并行。**
>
> - **主干定位**：跨平台运行的唯一主干是「本地二进制信号重映射」——进程级 syscall 拦截 → 查表转换 → 注入目标平台。这条路一步到位，不做「先 WSL2 后推翻」的双轨路径。
> - **WSL2 降级为可选加速路径**：WSL2 可用时作为 ELF 快速通道（透明）；不可用时**不报错**，自动切回本地重映射路径。**诊断 UI 不再把「WSL2 不可达」显示为红色错误**，而是「ELF 执行模式：本地重映射（实验性）」。
> - **Remote（远程节点）为远期选项**：仅用于本地无法承载的场景（如 macOS 专属硬件），不是当前交付依赖项。
> - **B1/B2 升格为主干正式载体**：B1 规则映射是本地重映射的**逻辑层**，B2 双梯形网络为未来数据增强层，不再是「默认关闭的实验分支」。
> - **交付节奏按 syscall 分组渐进**：文件读写类 → 内存管理类 → 进程/线程类 → 设备/网络类（每组 10 条）。每一组完成后，该组覆盖的程序即可在目标平台本地直跑，用户看到「驭灵跑通了一个 Linux 程序」，而非「驭灵调用了 WSL2」。
> - **Mach-O 边界**：在 ELF 路径跑通 ≥50 常见 syscall 前，Mach-O 保持「macOS 执行：开发中」的识别状态，**不作为失败显示**、不发送远程节点。
>
> **禁止事项（硬性）**：禁止以「WSL2 可用」为验收先决条件构建 ELF 执行宣称；禁止把「WSL2 不可达」写成红色失败；禁止未完成本地重映射主干前把 Remote 节点作为替代交付。北极星仍然有效；所有阶段交付以「本地可验证」为准。

## 1. 产品形态：三体合一

| 角色       | 形态        | 二进制                | 职责                                                      |
| -------- | --------- | ------------------ | ------------------------------------------------------- |
| **道体内核** | 常驻守护进程    | `daoti-daemon`     | 静默监听三系统、周期感知→推演→执行、发布事件、主动告警                            |

- **Tauri 桌面**：`cargo build -p daoti-ui --features ui`，内置 WebView2

## 3. 核心数据流：感知 → 推演 → 执行

```
┌──────────────────────────────────────────────────────────────┐
│                    daoti-daemon (常驻)                        │
│                                                              │
│  WindowsSensor ─┐                                            │
│  Wsl2Sensor ────┤── mpsc(16) ──→ Coordinator ──→ EventBus    │
│  DockerSensor ──┘    │                    │          │       │
│                      │ 收敛窗口 600ms      │          ▼       │
│                      │                    │    HTTP/SSE ──→ 玄镜
│                      │                    │    EventLog (JSONL)
│                      │                    │    Notifier (Toast/Webhook)
│                      │                    ▼                   │
│                      │              RuleEngine               │
│                      │          (五行→卦象→指令)              │
│                      │                    │                   │
│                      │                    ▼                   │
│                      │          SafeCommandExecutor          │
│                      │     (白名单+超时+平台分派)            │
│                      │                    │                   │
│                      │                    ▼                   │
│                      │           ExecResult → 二次感知        │
└──────────────────────┴──────────────────────────────────────┘
```

### 关键设计决策

| 决策                      | 说明                                                    |
| ----------------------- | ----------------------------------------------------- |
| **mpsc Actor 模型**       | 感知器→协调者经 `tokio::sync::mpsc`（容量 16），禁止共享内存（R7）        |
| **收敛窗口 600ms**          | `SETTLE_GRACE` 合并同一采样轮内三感知器到达先后，避免重复干预                |
| **RuleEngine 主推演**      | 确定性规则引擎（五行映射表），经 `InferenceEngine` trait 可插拔；onnx 已移除 |
| **SafeCommandExecutor** | 白名单 + 禁止模式 + 超时兜底 + `shell=false`，所有子进程调用经此           |
| **事件总线**                | `tokio::sync::broadcast`，daemon 唯一事件源（R8），前端只读消费      |
| **优雅停止**                | `CancellationToken`，感知器/协调者/HTTP server 统一管控          |

## 5. daoti-core：纯逻辑核心

**位置**：`crates/daoti-core/src/`

### 5.1 Sensor 感知层

```
sensor/
├── mod.rs         # Sensor trait, SensorState, SensorSnapshot, FusionState, WuxingHealth
├── windows.rs     # WindowsSensor（检测 Docker Desktop 服务状态）
├── wsl2.rs        # Wsl2Sensor（检测 WSL 发行版 + dockerd）
└── docker.rs      # DockerSensor（docker info 容器数/版本）
```

**Sensor trait**：`async fn collect(&self) -> SensorState`，返回 `Send` future 以支持 `tokio::spawn`。

**FusionState**：三感知结果融合 → `wuxing_health()` → `WuxingHealth { metal, wood, water }`（0\~1 浮点）。

**五行映射**：金=Windows / 木=WSL2 / 水=Docker。

### 5.2 Decision 推演层

```
decision/
├── mod.rs          # Decision 结构（priority/pathway/gua/confidence/explanation/commands）
├── engine.rs       # InferenceEngine trait + RuleEngine（确定性规则引擎）
├── causal_adapter.rs  # CrossPlatformCausalAdapter（五行健康度→决策）
└── command_gen.rs     # PlatformCommandGenerator（决策→平台自适应指令+白名单）
```

**推演流程**：

1. `WuxingHealth` → `CrossPlatformCausalAdapter::interpret()`
2. 产出 `Decision`：包含 `priority`（docker\_first/wsl2\_first/windows\_first/no\_action）、`pathway`、`gua`（坎/震/乾）、`commands`
3. `RuleEngine` 为默认实现（`InferenceEngine` trait），始终可用
4. Hebbian 慢调节（`SlowLearner`）+ 参数库，`learning` feature 门控默认关闭（P3-2）

### 5.3 Executor 执行层

```
executor/
├── mod.rs     # CommandSpec, ExecResult, PlatformExecutor trait
└── safe.rs    # SafeCommandExecutor（白名单+禁止模式+超时兜底）
```

**SafeCommandExecutor**：

- 白名单校验：允许的命令模式（如 `wsl.exe`, `docker`, `sc`）
- 禁止模式：拦截 `rm -rf /`、`format`、`Remove-Item -Recurse` 等危险操作
- 超时兜底：每条命令独立超时，超时自动 kill 子进程
- 平台分派：`target` → Windows（PowerShell）/ WSL2（`wsl -d <distro>`）/ Docker（`docker exec`）
- 所有子进程 `Command::args` 传参（`shell=false`），防注入

### 5.4 Agent 主控

**`agent.rs`** — `CrossPlatformAgent`：

- 对外统一接口，编排 `感知→推演→执行→二次感知` 完整闭环
- `diagnose_and_fix()` → `DiagnosisReport`（含 `HealOutcome` 五类结局分类）
- 供 CLI `daoti heal` 和 daemon `POST /api/heal` 共享

### 5.5 Probe 探测

**`probe.rs`** — 自动探测三系统：

- `wsl -l -q` 获取 WSL 发行版列表
- `wsl -l -v` 获取发行版状态
- `sc query` 获取 Docker 服务名
- 探测失败回退默认值，绝不 panic

### 5.6 模式B：跨平台二进制信号重映射

**位置**：`crates/daoti-core/src/`（interceptor / codec / bilateral / learning）

分层（B0 → B1 → B2，逐级增强；WSL2 仅作为用户显式选择的外部执行环境，不作为本地解释器验收兜底）：

```
模式B 模块
├── interceptor/      # B1 规则映射：Linux syscall → Win32 + 状态账本 + 遥测
│   ├── mod.rs        #   SyscallEvent / TargetSyscall / SYSCALL_MAPPINGS（20 条确定性映射）
│   ├── state.rs      #   ProcessState（FD 表 / 内存表 / cwd / env / brk）
│   └── telemetry.rs  #   TelemetryCollector（四分类样本 + 覆盖率）
├── codec/            # B2 编解码：SyscallEvent ↔ Array1<f64>
├── bilateral/        # B2 双梯形网络（代码骨架，gate 默认旁路）
│   ├── network.rs    #   BilateralLadderNetwork::forward（纯数学）
│   ├── weights.rs    #   WeightsLoader（DAOTIBLT 二进制权重）
│   └── gate.rs       #   B2Gate（四条件上线裁决）+ validate_derived
└── learning/         # 学习闭环（learning feature 门控，默认关闭）
    ├── trajectory.rs #   决策轨迹持久化
    ├── hebbian.rs    #   HebbianRule（有界慢调节）
    ├── params.rs     #   ParameterLibrary（参数库）
    └── slow.rs       #   SlowLearner（可观测慢调节）
```

- **B0 格式识别与分派**（部分可用）：`detect_binary_format` 可识别 ELF/PE/Mach-O；当前仅受控 ELF/ET_DYN 入口及 Mach-O/PE fixture 提供解析/契约证据，真实 libc 和通用执行能力不得据此宣称。
- **B1 规则映射**（逻辑层）：20 条确定性 syscall→Win32 映射、状态账本和降级决策已实现；不是完整 syscall 拦截/注入，也不是通用跨平台运行时。
- **B2 双梯形网络**（**代码骨架**）：网络数学/codec/gate/权重加载已实现，但训练条件尚未满足，gate 默认旁路；fixture/契约测试不构成真实能力证据。

## 6. daoti-daemon：守护进程

**位置**：`crates/daoti-daemon/src/`

### 6.1 Actor 编排

**`actor.rs`** — mpsc Actor：

```
ActorHandle::spawn()
  ├─ WindowsSensor ──→ mpsc::Sender
  ├─ Wsl2Sensor    ──→ mpsc::Sender
  ├─ DockerSensor  ──→ mpsc::Sender
  └─ Coordinator   ←── mpsc::Receiver
       ├─ apply_sense()      → FusionState
       ├─ SETTLE_GRACE 600ms  → 收敛窗口合并
       ├─ health_changed()   → 仅实质变化才推演
       ├─ infer_and_act()    → RuleEngine.interpret() → SafeCommandExecutor
       ├─ publish_sense/decide/execute/result  → EventBus
       └─ P0-6 notifier.notify()  → fire-and-forget 告警
```

### 6.2 HTTP/SSE 事件出口

**`http.rs`** — axum 0.7 路由：

| 方法   | 端点                                       | 用途                               |
| ---- | ---------------------------------------- | -------------------------------- |
| GET  | `/api/health`                            | 健康检查（含 P2-2 背压指标）             |
| GET  | `/api/events`                            | SSE 事件流（实时推送给玄镜）                 |
| GET  | `/api/events/history?before_seq=&limit=` | 历史事件分页拉取（P0-5）                   |
| GET  | `/api/snapshots`                         | 快照列表（元数据）                        |
| GET  | `/api/snapshots/:ts`                     | 单条快照详情                           |
| GET  | `/api/snapshots/diff?ts1=&ts2=`          | 快照对比（P1-6）                       |
| POST | `/api/heal`                              | 一键修复（P0-7，调用 CrossPlatformAgent） |
| POST | `/api/run`                               | 模式B B0 跨平台运行（格式检测→分派执行）         |
| POST | `/api/b1/run`                            | 模式B B1 规则映射（syscall→Win32 + 降级）   |

安全约束：

- 仅绑定 `127.0.0.1:17890`
- CORS 白名单：`localhost:5173` / `tauri://localhost` / `http://tauri.localhost`
- CSP：`default-src 'self'; connect-src 'self' http://127.0.0.1:17890; ...`

### 6.3 EventLog 持久化

**`eventlog.rs`** — JSONL 格式落盘：

- 事件追加写入 `~/.daoti/events/daoti_events.jsonl`
- 历史分页读取：从文件末尾反向逐行读取（8KB 分块），支持 `before_seq` + `limit`
- daemon 重启后历史仍可读（持久化）

### 6.4 Notifier 告警

**`notifier.rs`** — 双通道通知（P0-6）：

```
CompositeNotifier
├─ WindowsToastNotifier    # PowerShell 调用原生 Toast API
└─ WebhookNotifier         # ureq HTTP POST JSON
```

- 触发点：`actor.rs` `infer_and_act()` 中 `decision.commands` 非空时
- fire-and-forget：`tokio::spawn_blocking` 隔离，失败不影响主流程
- Windows Toast：临时 `.ps1` 文件（UTF-8 BOM）调用 `Windows.UI.Notifications.ToastNotificationManager`
- Webhook：3 秒超时，企业微信/钉钉兼容格式

### 6.5 单实例锁

**`main.rs`** — `acquire_single_instance()`：

- PID 文件 `~/.daoti/daemon.pid`
- 存活检测 + 陈旧清理
- 重复启动返回明确错误

| `daoti daemon start/stop/status/restart` | `daemonctl`            | 守护进程生命周期管理                            |

**HealOutcome 五类结局**（P0-7）：

| 结局               | 条件                      | 退出码 |

| `NoAction`       | 无命令且 pathway=no\_action | 0   |

| `PartialSuccess` | 部分成功                    | 1   |
| `Timeout`        | 至少一条超时                  | 1   |
| `Failure`        | 全部失败                    | 1   |

## 10. 安全模型

| 层面         | 措施                                                         |
| ---------- | ---------------------------------------------------------- |
| **网络**     | daemon 仅绑定 `127.0.0.1`，不对外暴露                               |
| **CORS**   | 来源白名单（localhost:5173 / tauri://localhost），非白名单不返回 ACAO 头   |
| **CSP**    | `default-src 'self'; script-src 'self'`，禁止外部脚本             |
| **执行器**    | SafeCommandExecutor 白名单 + 禁止模式 + `shell=false` + 超时兜底      |
| **Bun 红线** | 前端禁止 `exec()`/`spawn()`/`child_process`/系统目录写操作            |
| **Actor**  | mpsc 通道通信，禁止共享内存（R7）                                       |
| **优雅停止**   | CancellationToken 统一管控，kill 前完成当前轮推演                       |
| **错误处理**   | 全局禁止 `unwrap()`/`expect()`，统一 `anyhow` + `thiserror` + `?` |

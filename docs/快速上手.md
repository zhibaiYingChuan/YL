# 驭灵（道体）快速上手

> 本文面向**首次使用的终端用户**：5 分钟内完成安装 → 初始化 → 跑通第一个跨平台命令。
> 最终目标见各技术文档顶部的「北极星」声明：Windows / Linux / macOS 三平台任意软件互调。

---

## 0. 先看这里：当前能做什么

| 能力 | 状态 |
|------|------|
| 三系统状态感知与一键修复（`daoti status` / `daoti heal`） | ✅ 可用 |
| Windows 宿主运行受控 PE32+ 控制台 fixture | ⚠️ 仅 fixture/契约证据，不代表通用 PE 能力 |
| Windows 宿主运行静态 x86_64 ELF | ⚠️ 本地解释器路径已具备；当前 `hello_libc.elf` 仍需通过 stdout 回归验收 |
| Windows 宿主运行动态 ELF | ❌ 当前不支持，仍依赖 WSL2/Ubuntu 等外部执行环境 |
| B1 syscall 映射 | ⚠️ 纯逻辑映射、状态账本和降级决策；不是完整 syscall 拦截/注入或自主运行时 |
| B2 双梯形网络 | ⚠️ 实验骨架，默认旁路；不是生产执行引擎 |
| Mach-O（macOS 二进制） | ⚠️ 通过远程 macOS 节点执行，需配置节点 endpoint/token |
| 远程 macOS 执行节点 | ✅ `daoti-macos-node`，接收 base64 Mach-O 并返回 stdout/stderr/exit_code |
| 安装包（`.msi` / `.deb` / `.dmg`） | Windows `.msi` / `.exe` ✅ 已可用；Linux/macOS ⏳ 构建中 |

> 当前版本定位：**Windows 原生执行 + 静态 ELF 本地解释器 MVP + PE 解释器第一竖切 + 远程 macOS 节点协议**。动态 ELF 真实执行仍未闭环；Mach-O 远程执行需配置 macOS 节点，不宣称 Windows 本地执行。

## 1. 远程 macOS 节点

在 macOS 节点上启动服务：

```bash
DAOTI_MACOS_NODE_TOKEN='change-me' cargo run -p daoti-macos-node
```

节点提供 `GET /health` 和 `POST /execute`，请求必须携带 `X-Daoti-Token`。`/execute` 接收 `filename`、`binary_base64`、`args` 和 `timeout_ms`，返回 `stdout`、`stderr`、`exit_code`。客户端配置 `macos.endpoint` 与 `macos.token`；生产环境使用 HTTPS，回环 HTTP 仅用于本地测试。

## 2. 安装（约 2 分钟）

当前为**源码编译**（安装包构建完成后可跳过本步，直接双击安装）。

```powershell
# 1) 获取源码
git clone <your-repo-url> daoti
cd daoti

# 2) 编译（首次需下载 Rust 依赖，约几分钟）
cargo build --workspace --release
```

编译产物：
- `target/release/daoti-daemon.exe` —— 守护进程（道体内核）
- `target/release/daoti.exe` —— 命令行（令牌）

> Windows 一键安装包：`.\scripts\build-release.ps1`（Linux/macOS：`bash scripts/build-release.sh`）。

---

## 2. 初始化（约 1 分钟）

```powershell
# 自动探测三系统（Windows / WSL2 / Docker），生成 ~/.daoti.toml
daoti init

# 查看三系统「气」的状态与判词
daoti status
```

期望输出示例：三系统健康度 + 五行判词（金/木/水）。

## 3. 跑通第一个跨平台命令（约 2 分钟）

```powershell
# 把一个 Linux 的 ELF 程序放到当前目录，直接运行（自动识别格式并托管执行）
daoti run ./hello.elf
```

- 若是静态 x86_64 ELF → 尝试本地解释器路径；当前以 `hello_libc.elf` stdout 回归通过作为完整验收标准
- 若是动态 ELF → 当前不支持本地解释，需使用外部 Linux 执行环境
- 若是 PE → 仅受控 PE32+ 控制台 fixture 有验证路径，不代表任意 PE 可执行
- 若是 Mach-O → 当前只识别格式，不执行
- 未知格式 → 明确报错，不会静默失败

---

## 4. 守护进程（自动启动，无需手动）

**打开玄镜即自动拉起守护进程**（`daemon` 常驻后台，玄镜关闭后仍继续守护）。

CLI 手动管理命令（可选，用于排查/重启）：

```powershell
daoti daemon status     # 查看运行状态
daoti daemon restart    # 重启
daoti daemon stop       # 停止
```

守护进程会静默监听三系统，遇异常主动告警并尝试自动修复。

## 5. 常见问题（FAQ）

**Q1：没装 WSL2 会怎样？**
`daoti init` 会探测不到 WSL2，三系统中「木」标记为不可达，其余功能正常。需要运行 Linux 程序时请先装 WSL2（`wsl --install -d Ubuntu`）。

**Q2：Windows 上怎么跑 Linux 程序？**
当前仅对受控 x86_64 ELF/ET_DYN fixture 尝试验证路径；真实 `hello_libc.elf` 尚未通过 stdout 端到端回归，因此不能宣称 libc 或静态 ELF 通用能力已完成。动态 ELF 仍不支持通用本地解释，WSL2/Ubuntu 仅可作为用户显式选择的外部执行环境。

**Q3：Linux 上怎么跑 Windows 程序？**
PE→Linux 尚未实现；当前没有可交付的 PE 本地解释器或兼容层。

**Q4：报错「daemon 离线」？**
先 `daoti daemon start`，再刷新玄镜页面。
